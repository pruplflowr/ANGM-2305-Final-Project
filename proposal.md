## Description
This is a narrative game with multiple branching paths and endings. Similar to a choose-your-own-adventure game, the ending you get will be determined by the choices you made previously.

## Features
- User inputs through the terminal
	- This game will take advantage of user-based choices to progress the story. For example, a 
  branching path may have three choices. The user can select option 1, 2, or 3 and recieve a
  different outcome for each.
- A story that reponds to the user's choices
	- A different outcome will be presented depending on what the user picked. This will be done
    through if statements. For example, if the user chose 1, outcome A will happen. If the user
    typed 2, outcome B will happen.

## Challenges
- Branching narrative: I will need to plan out all the possible choices and endings before I start coding the game. I am planning to use Twine for this. It will be my first time using it, but it is a tool used specifically for this genre of writing.
- User inputs that are not an option: If the choices are between 1 and 3 and the user types 4, the game needs to respond accordingly. This can be done using the else statement, which acts as a catch-all for all other options.
- Quitting the game: The user also needs a way to quit the game. The game needs to constantly look out for the input that will quit the game and respond accordingly.

## Outcomes
Ideal Outcome:
- A full game the user can play start-to-finish with multiple endings depending on their choices. Visuals and formatting are present to help make reading the story easier and establish the look of the game. 5+ endings.

Minimal Viable Outcome:
- A full game the user can play start-to-finish with multiple endings depending on their choices. Visuals will still be present, but more effort will be dedicated to polishing the story and ensuring that code is functional. Endings range from 3-5.
